# 얼굴 홀로그램 굽기

분석 연출에 쓰는, 좌우로 훑는 얼굴 와이어프레임 루프를 만든다.
결과물은 `assets/hologram/face_hologram.webp` 하나다.

찍은 영상 → 얼굴 격자 → Blender 렌더 → 빛 번짐/알파 → 애니메이션 WebP.

## 한 번에 굽기

```powershell
.\tools\hologram\build.ps1 -Videos "C:\Users\012\Downloads\3d 영상" -Name face_hologram `
  -Sweep 14 -Thickness 0.0024 -Frames 72 -Res 512 -Fps 24 `
  -MeshSpacing 0.10 -HighlightSpacing 0.115 -ContourStep 3 `
  -Color "C93F5C" -Emit 1.0 -ShellTint "FBEAEE" -FilmAlpha `
  -TextureWash 0.22 -LinesFront `
  -Dots -DotScale 7 -DotColor "FF8DA1" `
  -Head -HeadDepth 0.95 -HeadRings 7 `
  -Scan -ScanSize 2.6 -ScanColor "F0537A" -ScanAlpha 0.85 -ScanThickness 0.02
```

현재 결과: 512px, 72장, 24fps, 3초 루프, 약 1.2MB.

메시를 이미 갖고 있으면 `-Mesh scan.obj`, 아무것도 없이 파이프라인만
확인하려면 인자 없이 실행한다(Blender 내장 Suzanne 으로 렌더된다).

## 진짜 3D로 복원하기 (사진측량) — 지금 촬영본으로는 실패했다

**2026-08-25 시도 결과: 사람이 복원되지 않았다.** 눈높이 영상(한 바퀴 완주,
91장 중 72장 정합, 재투영 오차 0.93px)으로 COLMAP 전체 파이프라인을 돌렸는데,
복원된 건 사람이 아니라 **사무실**이었다. 희소 복원 6026점 중 카메라 궤도
중심(=머리가 있어야 할 자리) 반경 1.0 안에 **단 2점**, 조밀 복원 366,763점
중에는 **0점**. 딱 그 자리만 구멍이 나 있었다.

원인은 사진측량의 고전적인 한계다. 매끈한 피부에는 추적할 질감이 없고 검은
머리카락은 빛을 먹는다. 반대로 책상·창틀·모니터·바닥 타일은 특징이 넘쳐서
그쪽만 복원된다. 역광과 카톡 압축이 더 얹혔다.

**다시 시도할 거면** 얼굴에 질감을 만들어 주는 수밖에 없다 — 확산광으로 고르게
밝히고, 역광을 피하고, 가능하면 무늬 있는 모자나 스티커 같은 기준점을 붙인다.
그렇게까지 할 값어치가 있는지 먼저 따져라. 지금 연출은 **실제 사진 위에 격자를
얹는 방식**이라 사진측량 없이도 그 사람 얼굴이 그대로 보인다.

아래는 파이프라인 사용법이다. 촬영본이 나아지면 그대로 쓸 수 있다.

```powershell
.\tools\hologram\photogrammetry.ps1 -Video "C:\...\눈높이한바퀴.mp4"
# 끝나면 안내에 나오는 대로:
.\tools\hologram\build.ps1 -Mesh <head_mesh.ply> -Bounds <head_bounds.json> -Sweep 34
```

**영상 하나만 쓴다.** 여러 번 나눠 찍은 것을 합칠 수는 없다 — 그 사이 고개
각도와 표정이 달라지기 때문이다. 한 번에 한 바퀴를 돈 영상이어야 한다.
눈높이로 도는 게 제일 좋다.

COLMAP 이 필요하다 (CUDA GPU 필수):

```powershell
curl.exe -L -o colmap.zip https://github.com/colmap/colmap/releases/download/4.1.1/colmap-x64-windows-cuda.zip
Expand-Archive colmap.zip -DestinationPath $env:LOCALAPPDATA\colmap
```

Meshroom 은 쓰지 마라 — 배포 파일이 9.5GB 인데다 받는 속도가 느리다.
COLMAP 은 342MB 로 같은 일을 한다.

파이프라인이 하는 일:

1. 프레임 추출 (8fps)
2. `feature_extractor` → `exhaustive_matcher` → `mapper` : 카메라가 어디서 찍었는지 푼다
3. `image_undistorter` → `patch_match_stereo` → `stereo_fusion` : 조밀 점구름
4. `head_bounds.py` : 카메라 궤도로 **머리 위치·위쪽·정면**을 구한다
5. `crop_cloud.py` : 머리 주변 점만 남긴다
6. `poisson_mesher` : 메시로 만든다

4번이 핵심이다. COLMAP 좌표계는 방향이 정해져 있지 않아서 그대로 렌더하면
머리가 비스듬히 누운 채 아무 데나 본다. 촬영이 머리 주위를 도는 궤도라
카메라 위치만으로 세 가지를 다 구할 수 있다 — 궤도의 한가운데가 곧 머리,
카메라 Y축(화면 아래쪽)들의 평균을 뒤집으면 위쪽, 가장 정면으로 찍힌 컷의
카메라 방향이 얼굴의 정면이다.

5번을 4번보다 먼저 하면 안 된다. COLMAP 이 복원하는 건 사람이 아니라 **방
전체**라, 자르지 않고 메시로 만들면 책상과 의자까지 붙은 덩어리가 나온다.
자를 때 점의 법선을 그대로 들고 나가야 한다 — `poisson_mesher` 가 법선 없이는
면을 못 만든다. 그래서 Blender 로 자르면 안 되고(느슨한 점의 법선을 유지하지
않는다) `crop_cloud.py` 가 PLY 를 직접 다룬다.

VRAM 이 4GB 면 `-DenseSize 1000` 을 넘기지 마라. 조밀 복원은 뷰당 10초쯤
걸려서 72장이면 25분 안팎이다.

## 다시 찍는다면

지금 쓴 영상은 얼굴 격자를 뽑기엔 통과했지만 아쉬운 점이 있었다.
다시 찍을 거면 이것만 지켜도 결과가 확 좋아진다.

- **역광을 피한다.** 창을 등지고 앉으면 얼굴이 어두워지고, 카메라가 창을
  지날 때마다 자동노출이 출렁인다. 창을 마주보거나 옆으로 두고 앉아라.
- **눈을 뜨고 한 점을 본다.** 눈을 감으면 눈꺼풀 형태로 격자가 잡힌다.
- **카메라가 돌고 사람은 가만히 있는다.** 지금 영상은 잘 지켜졌다.
- **눈높이 한 바퀴가 제일 중요하다.** 격자는 정면에 가까운 컷에서 뽑는다.
  위/아래 각도는 좋은 컷을 고를 후보를 늘려줄 뿐이다.
- 카톡으로 옮기면 화질이 깎인다. USB 나 드라이브로 원본을 옮겨라.

`build.ps1` 은 모든 프레임에서 얼굴을 찾아 **크기 × 정면도³ × 선명도** 로
점수를 매기고 1등을 쓴다. 정면도는 3D 랜드마크로 얼굴 평면의 법선을 구해
재기 때문에 좌우 각도뿐 아니라 위아래로 젖혀진 것도 걸러낸다.

## 조절할 만한 값

| 인자 | 기본 | 설명 |
|---|---|---|
| `-Sweep` | 0 | 좌우로 훑는 각도(도). 0 이면 한 바퀴 돈다. 얼굴 격자는 뒤통수가 없으니 26 정도를 쓴다 |
| `-Thickness` | 0.006 | 선 굵기. 얼굴 격자는 촘촘해서 0.004 가 낫다 |
| `-Color` | 00E5FF | 선 색 |
| `-Dots` | 꺼짐 | 꼭짓점마다 점을 찍는다 |
| `-Frames` / `-Fps` | 96 / 24 | 장수와 재생 속도. 루프 길이 = Frames / Fps |
| `-Res` | 512 | 정사각 해상도. **ffmpeg 로 줄이지 말고 여기서 정해라** (아래 참고) |
| `-AlphaSteps` | 16 | 알파 양자화 단계. 용량에 가장 크게 영향을 준다 |
| `-DepthScale` | 1.0 | 얼굴 깊이 과장. 옆모습이 밋밋하면 1.2~1.4 |

## 색과 톤

흰 바탕에 얹는 것을 전제로 만들었다. 앱의 코랄 계열 다섯 단계를 쓴다
(`ScanTone`, `hologram_scan.dart`):

| | | |
|---|---|---|
| `mist` | `#FFD3DC` | 스캔선 잔상, 아바타 뒤 후광 |
| `line` | `#E4607A` | 2D 격자의 기본 선 (사진 구간을 켰을 때만 보인다) |
| `strong` | `#C93F5C` | 이목구비 윤곽, 지시선, 스캔선 |
| `glint` | `#FF8DA1` | 잡힌 점. 앱의 `AppColors.coral` 과 같다 |
| `label` | `#B08A92` | 계측 글자 |

**앱의 `brand`(#B02426)를 `strong` 에 그대로 쓰면 안 된다.** 코랄이 아니라
경고등처럼 빨개진다. 같은 계열에서 명도만 내려야 격자가 한 색으로 묶인다.
반대로 너무 밝게 잡으면 흰 화면에서 그냥 사라진다 — 사진 위 격자는 사진이
중간 톤이라 버티지만, 흰 카드 위에 뜨는 아바타는 명도를 낮춰야 읽힌다.

**색을 바꾸면 차가운 회색도 같이 데워야 한다.** 카드 테두리·진행 막대에
청회색(`#E3EAEF` 류)이 남아 있으면 코랄 화면에서 그것만 파랗게 뜬다.

얼굴 사진을 아바타에 입히므로 **`-FilmAlpha`(투명 배경 + 실제 색)로 굽는다.**
잉크 모드(`glow.py --ink`, 색 한 가지로 고정)는 선만 있던 시절의 방식이라
지금 쓰면 살색이 뭉개진다.

## 선이 살에 묻히지 않게

사진을 입힌 아바타에서는 **선이 살결에 묻혀 안 보인다.** 띄우는 것으로는 못 고친다.

**`-LinesFront` 로 선을 따로 그려 위에 얹는다.** 한 장을 두 번 렌더해서
(`frame_*.png` = 얼굴·머리·스캔면, `lines_*.png` = 격자·윤곽·하이라이트)
`compose.py` 가 겹친다. 깊이를 아예 겨루지 않으므로 어느 각도에서도 다 보인다.

띄우는 방식(`--line-lift`, `--line-swell`)을 먼저 시도했는데 **못 쓴다.**
`--line-lift` 는 카메라 쪽으로만 밀어서 볼·턱처럼 표면이 옆을 향하는 데서는
거의 안 듣고, `--line-swell` 로 바깥으로 부풀리면 이번엔 얼굴 옆으로 삐져나온다.
둘 다 살려 뒀지만 `-LinesFront` 를 쓰면 필요 없다.

곁들여 두 가지가 더 있어야 읽힌다.

- **`-TextureWash`** (0.22) — 사진을 흰색 쪽으로 띄운다. 2D 화면에서 사진 위에
  흰 막을 한 겹 얹던 것과 같은 처리다. 어둡게 덮으면 얼굴이 죽고 선도 같이 묻힌다.
  0.4 를 넘기면 얼굴이 창백해져서 "그 사람" 이 아니게 된다.
- **`-Color` 를 한 단계 진하게** (`#C93F5C` = `ScanTone.strong`). 살색은 밝고
  따뜻해서 밝은 코랄 선은 그 위에서 대비가 거의 없다. 2D 격자와 색을 맞출 필요는
  사진 구간을 켰을 때만 있다.

선이 다 보이면 **굵기를 오히려 줄여야 한다** (0.0034 → 0.0024). 가려지던 시절의
굵기를 그대로 두면 그물이 얼굴을 덮는다. 용량도 이만큼 늘어난다 (950KB → 1.2MB) —
선 픽셀이 그만큼 많아졌기 때문이고, 줄이려면 `-AlphaSteps` 를 내려라.

## 선 굵기와 하이라이트

**선은 얇게 긋되 진하게.** 굵은 선보다 가는 선이 정밀해 보인다. 격자 0.5px,
윤곽 0.7px, 훑고 지나가는 앞줄 0.8px 이다. 대신 선이 얇아질수록 어두운 배경
(머리카락·옷) 위에서 사라지기 쉬워서, 흰 받침을 1.2px 로 먼저 깔아 준다.

**잡힌 점은 하이라이트로 찍는다.** 진한 점으로 찍으면 밝은 사진 위에서
티끌처럼 보이고, 테두리를 두르면 얼굴에 박힌 구슬처럼 보인다. 흰 번짐 +
흰 심지 **두 겹만** 쓴다 — 윤곽선을 그리는 순간 하이라이트가 아니게 된다.
메이크업 앱이라 피부 위 광택으로 읽히는 편이 맞기도 하다.

**하이라이트는 이목구비 위에 고르게 뿌린다.** 번호를 일정 간격으로 세면
안 된다 — mediapipe 인덱스는 부위별로 뭉쳐 있어서 눈 주변에만 몰리고 볼은
텅 빈다. 윤곽선(눈·눈썹·코·입·얼굴선)에 쓰이는 정점만 후보로 두고
화면에서 일정 거리 이상 떨어진 것만 남긴다 (`--highlight-spacing`).

**2D 와 3D 가 같은 목록을 쓴다.** `face_to_mesh.py` 가 정한 `highlights` 를
사진 위 오버레이와 3D 아바타가 둘 다 쓴다. 따로 고르면 사진에서 반짝이던
자리와 아바타에서 반짝이는 자리가 달라져 이어져 보이지 않는다.

**색은 전부 코랄로 묶는다.** 흰 반짝임을 쓰면 이 화면에서 유일하게 색이
없는 요소가 되어 따로 논다 (`ScanTone.glint`). 3D 쪽 `-DotColor` 도 같은
값으로 맞춘다.

## 사진 구간은 기본으로 꺼져 있다

`HologramScan(photoStage:)` 가 기본 `false` 다. 사진을 훑는 앞 구간(빔·격자·
모프)을 빼고 **아바타부터 띄운다.** 분석이 언제 끝날지 모르는데 앞에 7초짜리
연출을 두면 결과가 그만큼 늦게 나오는 것으로 느껴진다. 아바타만 두면 서버가
오래 걸려도 화면이 계속 살아 있다 (4.6초 → 그 뒤로는 아바타가 계속 돈다).

구간표는 두 벌(`_short` / `_full`)이고 그림 부품도 그대로 남겨 두었다 —
되돌리려면 `photoStage: true` 하나만 주면 된다. 뷰어(`make_artifact.py`)는
`PHOTO_STAGE` 상수가 같은 일을 한다. 아래 절은 그 구간을 켰을 때 얘기다.

**사진이 없으면 아바타를 키운다** (`_zoom`, 기본 1.5). 맞출 상대가 없는데
사진 속 얼굴 크기 그대로 두면 넓은 카드에 얼굴만 덩그러니 작게 뜬다.
배율은 **짚는 지점에도 같은 중심으로** 걸어야 한다 — 라벨까지 밀면 화면 밖으로
나가므로 라벨은 그대로 둔다. 사진 구간을 켜면 배율은 반드시 1 이다.

## 사진이 아바타가 되는 구간 (photoStage: true 일 때)

**사진을 먼저 지우면 안 된다.** 예전에는 사진을 녹이고 격자만 남겼다가 3D 로
넘겼는데, 아바타가 실제 얼굴을 갖게 된 뒤로는 그 중간 구간이 "얼굴이 사라졌다"
로 보인다. 지금은 자리·크기를 맞춰 두고 바로 겹쳐 바꾼다 — 얼굴은 그대로 있고
입체감만 생긴다.

이게 성립하려면 **2D 격자와 3D 첫 프레임이 같은 자리·같은 크기**여야 한다.
세 가지를 맞춰 둔다.

1. **첫 프레임이 정면이다.** 스윕이 사인이라 0 에서 시작하고, 위젯이 이 구간에서
   처음 만들어지므로 애니메이션도 첫 프레임부터 돈다.
2. **자리를 재서 남긴다.** `measure_hologram.py` 가 첫 프레임의 알파 바깥
   사각형을 재서 `assets/hologram/<이름>.json` 에 적는다. 앱이 그 값으로
   아바타를 2D 격자의 바깥 사각형에 겹쳐 놓는다 (`HologramFit`).
3. **데모 사진이 정확히 3:4 다.** 잘라낼 때 비율을 유지한 채 줄인다 —
   가로세로를 따로 자르면 격자 좌표(사진 기준)와 화면 좌표가 어긋난다.

굽는 설정을 바꾸면 자리도 달라지므로 `build.ps1` 이 매번 다시 잰다.

## 실제 얼굴을 3D 아바타로

**사진을 3D 얼굴에 그대로 입힌다.** mediapipe 가 낸 2D 좌표가 곧 사진 안에서의
자리라서, 그 값을 UV 로 쓰면 원본 프레임이 정확히 얼굴에 맞는다
(`face_to_mesh.py` 가 `<mesh>_texture.jpg` 로 UV 와 같은 좌표계의 원본을 같이
남긴다 — **잘라낸 사진을 쓰면 어긋난다**).

사진을 입히려면 **굽는 방식이 달라진다.** 잉크 모드(`--ink`)는 밝기를 알파로
바꾸고 색을 한 가지로 뭉개서 텍스처가 통째로 죽는다. `-FilmAlpha` 를 쓰면
배경을 투명하게 렌더하고 색을 그대로 남긴다 (`glow.py --keep-color` 는 알파만
정리해 용량을 줄인다).

뒤통수에는 UV 가 없다. 얼굴 면과 뒤통수 면에 재질을 나눠 붙여야 사진 한
귀퉁이가 뒤통수에 늘어붙지 않는다 — `close_back()` 전에 면 개수를 세 두고
그 뒤 면들은 단색으로 칠한다.

## 아래로 내려가는 스캔선

`-Scan` 이 실제 판을 머리에 통과시킨다. 화면에 띠를 그리지 않는 이유는
그러면 앞뒤 구분이 없어 평면처럼 보이기 때문이다 — 실제 판은 머리에 가려지는
부분이 저절로 가려져서 "뚫고 지나간다" 로 읽힌다.

**한 방향으로만 내려간다.** 왕복시키면 훑는 게 아니라 흔들리는 것으로 보인다.
톱니파로 내리고 되돌아가는 순간에는 선이 머리 밖에 있어서(`_SCAN_SPAN` 을
머리보다 넓게 잡았다) 튀는 게 보이지 않는다. 2D 빔(`_BeamPainter`)도 같은
톱니파를 쓰고, 잔상은 선 **뒤쪽으로만** 끌린다 — 양쪽으로 번지면 띠가 되어
어디가 지금 지나는 줄인지 알 수 없다.

**판이 선으로 보이려면 두 가지가 다 필요하다.** 하나라도 빠지면 얼굴을 덮은
분홍 덩어리가 된다 (두 번 구워 보고 알았다):

1. **리그에 붙이지 마라.** 붙이면 머리가 좌우로 훑을 때 판이 같이 돌아
   카메라에 원판 면이 그대로 보인다. 머리는 제자리에서 돌기만 해서 안 붙여도
   통과 위치는 그대로다.
2. **매 프레임 카메라 쪽으로 눕혀라** (`scan_edge_on`). 카메라가 원근이라
   눈높이를 지날 때만 저절로 선이 된다. 위아래로 벗어나면 판의 면이 드러난다.

- **사각 판은 안 된다.** 각진 모서리가 얼굴 밖으로 튀어나와 "화면을 덮은 띠"가
  된다. 둥근 면(`--scan-size`)에 가장자리를 흐려야(`scan_material` 의 반경
  페이드) 선 끝이 자연스럽게 사라진다.
- 흐림은 **오브젝트 좌표**로 잰다. 월드 좌표로 재면 판이 오르내릴 때마다
  중심이 딸려 가서 흐림이 엉뚱한 데로 옮겨 간다.
- 옆날로만 보이므로 화면에 남는 굵기는 `--scan-thickness` 가 전부다. 0.02 가
  512px 에서 4px 남짓이다. `--scan-alpha` 는 선이라 0.85 로 진하게 둔다 —
  면이던 시절의 0.5 를 그대로 쓰면 선이 흐려 안 보인다.

스캔면을 넣으면 **정렬 측정이 망가진다.** 판이 머리보다 넓어서 바깥 사각형이
화면 전체로 잡힌다. 그래서 스캔면·머리·머리격자를 숨긴 전용 프레임(`align.png`)
을 따로 렌더해서 잰다 — **2D 마스크와 같은 범위**여야 한다. 머리까지 재면 그
넓이에 맞추느라 아바타가 확 작아진다.

## 3D 아바타와 분석 표시

마지막 구간은 **아바타(머리)에 분석 마스크가 씌워진** 장면이다.
`-Head` 를 주면 만들어진다. 네 겹이 겹쳐야 그렇게 읽힌다.

1. **머리** — mediapipe 격자는 얼굴 앞면만 있는 껍데기라, 그대로 돌리면
   아바타가 아니라 가면이 누워 있는 것으로 보인다. `close_back()` 이 테두리를
   뒤로 밀면서 고리를 쌓아 뒤통수를 닫는다.
2. **머리 격자** — 뒤통수에 선이 하나도 없으면 부피가 안 읽혀 방패처럼 보인다.
   얼굴 마스크보다 가늘고 옅게 (`--head-wire`, `--head-wire-scale`) 둘러야
   "아바타 위에 마스크" 로 층이 진다.
3. **굵은 윤곽선** — 얼굴 쪽 이목구비. 격자와 **같은 굵기로 그리면 묻힌다.**
   윤곽선만 따로 객체로 만들어 1.9배 굵게 뽑는다.
4. **부위 지시선** — `_AnalysisPainter` 가 이마 · 볼 · 턱선을 차례로 짚는다.

**두개골은 중간에서 얼굴보다 넓어져야 한다.** 반지름이 1 을 넘지 않으면
얼굴 윤곽 뒤에 통째로 가려서, 아무리 돌려도 머리가 안 보이고 계속 가면으로만
보인다 — 실제로 이걸 놓쳐서 여러 번 다시 구웠다. `--head-swell` 이 그 값이고
0 이면 안 보인다. 실제 머리도 관자놀이 뒤쪽이 얼굴보다 넓다.

스윕도 같이 키워야 한다. 뒤통수가 닫히기 전에는 크게 돌리면 가면 속이
드러나서 18도로 묶어 뒀지만, 닫은 뒤에는 34도까지 열어야 머리 부피가 보인다.

**수치를 지어내지 않는다.** 어디를 보고 있는지만 짚고, 그럴듯한 숫자는
띄우지 않는다. 앞이 보이지 않는 사용자에게 지어낸 분석은 오답보다 나쁘다는
원칙이 화면에도 그대로 걸린다.

주의: Wireframe 모디파이어는 **면에서만** 선을 뽑는다. 면과 별개인 윤곽선이
통째로 사라지므로, 다듬어진 격자는 면을 지운 복제본을 커브로 바꿔 두께를 준다
(`holo_prepared` 표시가 그 분기다). 리토폴로지도 같은 표시로 건너뛴다 —
QuadriFlow 를 돌리면 성글게 만든 격자가 도로 잘게 쪼개진다.

## 표면과 선은 따로 만든다

**선을 줄이려고 표면까지 성글게 하면 안 된다.** 점을 솎아 다시 삼각분할하면
경계에서 삼각형이 버려져 얼굴에 구멍이 뚫린다 — 아바타에서 이마·볼이 뜯겨
나간 것처럼 보인다.

- **표면**: mediapipe 삼각망을 그대로 쓴다 (`tesselation_faces`). 빈틈이 없다.
- **선**: `--mesh-spacing` 으로 따로 성글게 만든다.

Blender 로 넘길 때도 나눠야 한다. `from_pydata` 에 면을 주면 그 면의 변까지
메시에 생기므로, 면을 지우고 남은 변으로 와이어를 만들면 표면 삼각형이
그대로 딸려 온다. **그릴 선은 `holo_lines` 에 적어 두고 그것만으로 새로 만든다.**

두 가지가 더 필요하다.

- **눈 구멍을 메운다.** mediapipe 삼각망은 눈알 자리를 비워 두는데, 그대로면
  그 구멍으로 뒤통수 안쪽이 비쳐 눈에 흰 덩어리가 앉는다 (`fill_loop`).
- **선을 표면에서 띄운다.** 같은 자리에 있으면 반쯤 묻힌다. 카메라 쪽으로
  `--line-lift` 만큼 옮겨야 마스크가 얼굴 위에 얹힌 것으로 보인다.
- **머리 격자는 뒤통수에만 두른다.** 얼굴까지 두르면 촘촘한 표면 삼각형이
  전부 선으로 나와 얼굴이 그물로 덮인다.

## 윤곽선 줄이기

2D 화면에서는 **윤곽선이 격자보다 훨씬 많다.** mediapipe 윤곽은 눈·입술이
아주 촘촘한 폴리라인이라 원본 그대로면 124선이다 (격자는 66선). 선을 줄이려면
격자만 성글게 해서는 소용없고 윤곽도 같이 솎아야 한다.

`--contour-step` 이 그 값이다. 선을 무작정 빼면 눈·입이 끊긴 조각이 되므로,
**윤곽을 사슬로 이어 붙인 뒤 사슬을 따라가며 솎는다** — 모양은 그대로 두고
선 개수만 준다. 3 이면 124 → 46 선이다.

## 격자 밀도

mediapipe 기본 삼각망은 1322 선이라 얼굴에 얹으면 **그물처럼** 보인다.
`face_to_mesh.py` 가 점을 고르게 솎은 뒤 다시 삼각분할해서 **격자 188선**으로
줄이고, 사라지는 이목구비는 **윤곽 124선**을 따로 얹어 살린다.

- `--mesh-spacing` (기본 0.058) 이 간격이다. 키우면 더 성글어진다.
- 원래 삼각망에서 선을 골라 빼면 조각조각 끊긴다. 남긴 점으로 **새로**
  삼각분할해야 고르고 이어진 격자가 나온다 (scipy Delaunay).
- 같은 선 목록을 사진 위 격자와 3D 홀로그램이 **함께 쓴다.** 밀도가 다르면
  떠오를 때 다른 격자로 보인다.

## 재고 있는 것처럼 보이게

아바타만 떠 있으면 "그림" 이다. 세 가지가 그걸 "재는 창" 으로 바꾼다.

- **눈금자** (`_GraticulePainter`) — 가장자리를 따라 눈금을 새기고, 걸린 눈금
  하나가 **한 칸씩 끊어** 옮겨 다닌다. 부드럽게 흐르면 계측이 아니라 장식이 된다.
  눈금에 값은 붙이지 않는다 — 지어낸 숫자는 안 쓴다.
- **조준틀** (`_AnalysisPainter._reticle`) — 부위마다 네 귀퉁이가 조여 들어와
  물린다. 점을 찍어 두면 "표시해 뒀다" 이지만, 조여 들어오면 "지금 재고 있다" 다.
  다 조인 뒤에야 속 빈 원이 남는다.
- **표시등** — 계측 줄 앞의 5px 점이 깜박인다. 멈춘 화면과 일하는 화면을 가르는 건
  결국 이런 작은 깜박임이다.

부위는 일곱이다 — **이마·눈썹·눈가·볼·코·입술·턱선.** 짚는 순서는 **위에서
아래**로, 스캔선이 내려가는 방향과 같아야 훑으면서 하나씩 잡는 것으로 읽힌다.
라벨은 좌우로 번갈아 두고 세로로 벌려 놓는다 — 같은 쪽에 몰리면 지시선이
서로를 넘는다. 개수를 늘리면 연출도 늘려야 한다(4.6 → 5.6초).

**짚는 점은 얼굴을 따라 움직인다.** 아바타가 좌우로 훑는데 점이 고정돼 있으면
이마를 짚던 점이 관자놀이로 밀려난다. 각도를 어림해 계산하지 않고 **구울 때
잰 값**을 쓴다 — `--zones "이마=151,눈썹=105,..."` 로 mediapipe 정점 번호를
넘기면 매 프레임 카메라에 투영해 `<이름>_zones.json` 으로 남기고, 앱이 그걸 읽는다.

두 가지가 맞아야 어긋나지 않는다.

- **아바타와 표시가 같은 배치 셈을 써야 한다** (`HologramPlacement`). 따로
  계산하면 조준틀이 얼굴에서 미끄러진다. `contain` 여백은 위젯이 그리는 그림에
  이미 들어 있어서 `transform` 에는 없다 — 좌표를 직접 옮길 때만 더한다.
- **지금 몇 번째 프레임인지를 어림하면 안 된다.** 처음엔 시계로 짚었는데
  못 쓴다 — 재생은 그림이 다 실린 뒤에 시작하고(마운트보다 수백 ms 늦다)
  프레임이 밀리거나 건너뛰면 어긋남이 **계속 커진다.** 그게 그대로
  "조준틀이 지 맘대로 움직인다" 로 보인다.

  그래서 재생을 우리가 한다. 앱은 `ui.instantiateImageCodec` 으로 코덱을 직접
  돌리고(`_Hologram`), 뷰어는 `ImageDecoder` 로 프레임을 뽑아 캔버스에 그린다.
  **그린 번호가 곧 화면에 있는 프레임**이라 어림이 없다. 느려지면 같이 느려질
  뿐 어긋나지 않는다.

  주의할 것 셋. (1) 프레임을 전부 풀어 두지 마라 — 512px 72장이면 75MB다.
  한 장씩 그리고 바로 버린다. (2) 기다릴 때 `Future.delayed` 를 쓰면 취소가
  안 돼서 위젯이 사라진 뒤에도 타이머가 남는다(위젯 테스트가 `!timersPending`
  으로 걸린다) — `Timer` 를 붙잡고 있다가 `dispose` 에서 취소해라.
  (3) 뷰어에서는 `await dec.completed` 만으로 부족하다. `dec.tracks.ready` 를
  먼저 기다리지 않으면 `selectedTrack` 이 null 이다. 그리고 **한 장을 그린
  뒤에** `<img>` 를 숨겨라 — 순서를 바꾸면 첫 프레임까지 화면이 비고,
  뒤에 있는 탭에서는 rAF 가 안 돌아 영영 빈 화면이 된다.

연출이 끝난 뒤에도 도는 티커(`_spin`)가 따로 있다. 없으면 5.6초에 화면이 통째로
얼어붙어서, 서버를 더 기다리는 동안 죽은 화면이 된다.

**뷰어(`make_artifact.py`)도 같은 값을 쓴다.** 여기만 고정 좌표로 남겨 두면
링크로 보는 사람에게는 짚는 점이 안 움직인다(실제로 그렇게 남아 있었다).
다만 기준 시각이 다르다 — 움직이는 WebP 는 **붙는 순간부터** 저절로 도니까
재생 버튼을 누른 때가 아니라 `holo` 의 `load` 때를 재야 한다. 그리고 그
리스너는 `src` 를 넣기 **전에** 붙여야 한다. 데이터 URI 는 곧바로 실려서
나중에 붙이면 load 를 놓친다.

**조준틀이 물리는 순간마다 삐 소리를 붙인다.** 그림과 소리가 같은 순간에 걸려야
"저기를 재고 있다" 로 읽힌다 — 어긋나면 둘 다 장식이 된다. 위젯의 큐와
`make_soundtrack.py` 의 `ZONES` 가 같은 식을 쓴다.

## 기계음

```powershell
python tools\hologram\make_sounds.py
```

`assets/hologram/sfx/` 에 5개를 합성한다 — 빔이 지나가는 소리, 특징점이
잡히는 핑, 홀로그램이 올라오는 소리, 완료음, 그리고 분석 중 깔리는 저음.

**전자음이고, 기본 단위는 두 음이 붙은 한 쌍(삐빅)이다.** 좁은 대역의 잡음으로
'공기' 소리를 만들던 때가 있었는데, 조용해서 좋기는 해도 기계가 일하는 소리로는
안 들렸다. 지금은 그 쌍을 되풀이한다 — "삐빅 … 삐빅 … 삐빅".

**간격이 일정하면 "삐삐삐삐" 로 뭉개진다.** 쌍 안은 좁게(18~22ms), 쌍 사이는
넓게(74~78ms) 벌려야 쌍으로 들린다 (`sequence()` 가 간격 목록을 받는다).

**음높이는 466 / 622 / 831Hz 다** (`_LOW`/`_HIGH`/`_TOP`). 예전엔 1.5~2.3kHz 였는데
너무 날카롭고, 하필 **자음이 사는 대역(2~4kHz)이라 안내를 가장 잘 덮는 자리**였다.
한 옥타브 넘게 내리니 귀도 편하고 TTS 와도 덜 부딪친다.

사각파를 그대로 쓰면 배음이 나이퀴스트를 넘어 접혀서 싸구려로 들린다.
홀수 배음을 18kHz 아래까지만 더해 만든다 (`beep()`).

**삐빅은 `hum_loop.wav` 안에 들어 있다.** 저음 위에 0.8초마다 한 쌍을 얹은
2.4초 루프다. 악센트를 그때그때 울리는 방식으로는 "계속 나는 소리" 를 못 만든다 —
울릴 일이 없는 구간에서 뚝 끊기고, 분석이 20초를 끌면 뒷부분이 통째로 조용해진다.
루프에 넣으면 서버가 얼마나 걸리든 박자가 유지된다.

박자 개수는 `round(length / beat)` 로 센다. `int()` 를 쓰면 2.4/0.8 이 부동소수로
2.9999… 라 **한 박자를 통째로 잃는다** (실제로 세 번 중 두 번만 들어갔다).

특징점마다 따로 울리지 않는다. 도는 삐빅이 이미 박자를 잡고 있어서 거기서 또
울리면 박자가 엉킨다. 악센트는 **부위가 조준틀에 물릴 때만** 얹는다(`lock_blip`,
-27 dBFS). 이것만 키우면 안내 문장이 통째로 씹힌다.

받아온 음원을 쓰지 않는 건 라이선스 때문만이 아니라 **소리 크기를 우리가
쥐고 있어야 하기 때문**이다. BeautyTalk 은 눈이 보이지 않는 사용자가 쓰고
안내는 전부 TTS 로 나간다. 기계음이 말소리를 덮는 순간 이 연출은 앱을
망가뜨린다. 유일하게 계속 나는 bed 는 -32 dBFS 로 깔았고, 여기에 0.5초마다 아주 작은 틱을
넣었다 — 켜져만 있는 게 아니라 **돌아가고 있는** 소리다. `ScanSfx.instance.enabled = false` 로 통째로 끌 수 있고,
TTS 가 말하는 동안은 `ScanSfx.instance.duck(true)` 로 0.5 → 0.14 까지 내린다.
**삐빅은 잡음보다 훨씬 잘 덮으므로 이 덕킹이 전보다 중요해졌다.**

## 화면 글귀와 같은 말을 읽어 준다

앱은 분석을 시작하면서 바로 `"○○를 분석 중이에요."` 를 읽는다
(`AppState._focusLine`). 예전에는 "살펴보고 있어요" 라고만 하고 부위 이름은 30%
지점에서야 나왔는데, 그때까지 **화면도 소리도 있는데 말만 없어서** 멈춘 것처럼
느껴졌다. 기다리는 동안 나가는 문장에도 부위 이름을 계속 끼워 둔다.

`make_artifact.py` 로 구운 뷰어도 `speechSynthesis` 로 같은 문장을 읽는다 —
글자로만 있는 게 아니라는 걸 링크 하나로 확인할 수 있다. 목소리는 기기마다
다르고 없을 수도 있어서 없으면 조용히 넘어간다. **영상(mp4)에는 말소리가 없다** —
오프라인 한국어 TTS 가 없다.

## 결과 화면 — 문제가 있는 자리를 짚는다

서버가 좌표(`box`)를 주면 그대로 쓰고, **안 주면 부위 이름으로 자리를 어림한다**
(`ProblemSpot.zoneOf`). 예전에는 좌표가 있을 때만 사진이 떴는데 실제로는 좌표
없이 오는 경우가 더 많아서, 결과에서 "어디가" 가 통째로 빠져 있었다.

자리 표는 **손으로 어림한 값이 아니라** `demo_face_points.json` 의 실제 얼굴
랜드마크에서 뽑았다. 눈대중으로 넣었다가 입술이 턱 아래에, 볼이 목에 찍혀서
다시 계산했다. 표가 mediapipe 의 좌우 이름을 그대로 따라가므로 **"왼쪽 볼" 을
사진 어느 쪽에 그릴지도 저절로 맞는다** — 거울상 여부를 따로 따질 필요가 없다.

**네모로 칠하지 않는다.** 테두리를 두른 구역과 번호를 쓰다가 걷어냈다.
그렇게 그리면 어디가 문제인지보다 네모가 먼저 보이고, 딱 떨어지는 네모는
서버가 재지도 않은 좌표를 잰 것처럼 보인다. 지금은 **가운데가 진하고 밖으로
스미는 코랄 얼룩**이다 — "이 언저리" 로 읽히고, 화장품 앱에 맞는 언어이기도 하다.
번호도 없앴다. 자리에 색이 번져 있으면 카드의 이름만으로 바로 이어진다.

진하기는 가운데 0.46 이 기준이다. 옅으면 사진 위에서 안 보이고, 진하면 그 자리
피부가 안 보여서 뭐가 문제인지 판단할 수가 없다. 고른 게 있으면 그것만 1.5배로
올리고 나머지는 0.28배로 내린다 — **차이가 작으면 눌러도 아무것도 안 짚힌 것처럼
보인다**(0.3배로 뒀다가 구분이 안 돼서 벌렸다). 그래도 아주 지우지는 않는다.
자리를 못 찾은 항목은 아예 안 그린다 — 어디인지 모르면서 아무 데나 칠하는 게 더 나쁘다.

**카드를 누르면 그 자리만 남는다.** 여럿을 한꺼번에 짚으면 어느 게 어느 카드인지
눈으로 못 잇는다. 고르면 나머지는 테두리만 옅게 남기고 물러난다 — 통째로 지우면
"다른 데도 있었나" 를 알 수 없다. 한 번 더 누르면 다시 전부 보인다.
화면을 못 보는 사용자에게는 짚어 준 게 안 보이므로 **말로 한 번 더 알려 주고**,
카드에 `Semantics(button: true)` 와 "두 번 누르면…" 안내를 붙였다 —
'누를 수 있음' 이 안 읽히면 이 기능은 없는 것과 같다.

`flutter test test/result_spots_render_test.dart` → `build/result_spots.png`.

**결과 화면을 카드 안에 넣을 때 분석 화면을 감싸는 껍데기가 높이를 이어받아야
한다.** `.analysing` 에 `flex:1; min-height:0; display:flex` 를 안 주면 안쪽
`.stage` 의 `flex:1` 이 기댈 곳을 잃어서 무대가 0px 로 찌그러지고 **아바타가
통째로 사라진다.** 실제로 그렇게 사라뜨렸다.

**뷰어도 분석이 끝나면 결과 화면으로 넘어간다.** 앱이 서버 응답을 받으면 곧바로
결과 단계로 가는 것과 같다 — 연출이 어디로 이어지는지가 안 보이면 반쪽이다.
뷰어의 결과 문장은 **예시**라고 화면에 적어 두었다. 서버가 준 문장이 아닌 것을
그냥 띄우면 분석 결과로 오해된다. 자리 표(`ZONE_BOX`)는 앱의 `_zoneTable` 과
같은 값이다 — 한쪽만 고치면 어긋난다.
결과 사진은 **즉시 한 번, 다음 프레임에 한 번 더** 그린다. rAF 로만 그리면
화면 뒤에 있는 탭에서 영영 안 그려지고, 즉시만 그리면 방금 바꾼 display 때문에
아직 예전 크기로 잰다.

## 앱 어디에 붙어 있나

메이크업 분석 탭의 **분석 중** 단계 (`lib/screens/tabs/makeup_tab.dart` 의
`_Analyzing`) 가 `HologramScan` 을 쓴다. 상태 문장과 진행 막대는 위젯 안으로
들어갔다 — 어두운 면 위에 얹혀야 읽힌다.

**흰 바탕이다.** 한때 딥 플럼 위 시안 네온이었는데, 앱의 나머지가 전부 밝아서
그 구간만 밖에서 굴러온 화면처럼 보였다. 지금은 앱과 같은 흰 바탕에 코랄로
칠한다. 화장품 인식 탭은 기존 `ScanningPhoto` 를 그대로 쓴다.

색을 바꾸려면 `ScanTone` 다섯 값과 **굽는 명령의 `-Color`/`-DotColor`/
`-ScanColor`/`-ShellTint` 를 같이** 고쳐야 한다. 2D 격자와 3D 아바타가 다른
색이면 겹쳐 바뀌는 순간 색이 튄다.

홀로그램만 따로 쓰고 싶으면 알파가 있는 애니메이션 WebP 라 이걸로 끝이다:

```dart
Image.asset('assets/hologram/face_hologram.webp', width: 240)
```

## 왜 이렇게 만들었나

**왜 사진측량이 아닌가.** 홀로그램은 텍스처 없이 형태만 쓴다. 사진측량은
텍스처가 강점인데 여기선 쓸모가 없고, 대신 역광·압축·머리카락에 약하다.
결정적으로 촬영본이 세 번에 나눠 찍혀서 그 사이 고개 각도와 표정이
달라졌는데, 사진측량은 세 바퀴 내내 피사체가 굳어 있어야 합쳐진다.
얼굴 격자는 한 컷으로 형태를 뽑고 격자가 처음부터 반듯해서
와이어프레임으로 쓰기에도 낫다.

**왜 투명 영상이 아니라 WebP 인가.** Android 쪽 `video_player` 가 알파를
살려주지 않는다. 애니메이션 WebP 는 Flutter 기본 `Image` 위젯이 알파째로
재생한다.

**왜 빛 번짐을 Blender 밖에서 하나.** Blender 5.x 가 컴포지터를 노드 그룹
방식으로 갈아엎으면서 Math·MixRGB 노드까지 사라져 버전을 심하게 탄다.
`glow.py` 에서 하면 다시 렌더하지 않고도 세기를 고칠 수 있다.

**왜 밝기를 알파로 쓰나.** 투명 배경에 직접 글로우를 그리면 번짐이 실루엣
경계에서 잘려나간다. 밝기를 알파로 삼으면 번짐이 알파째로 옅어져 잘리지
않는다. 대신 색을 알파로 나눠 되돌려야(un-premultiply) 합성 때 두 번
어두워지지 않는다.

**왜 알파를 양자화하나.** WebP 는 알파를 무손실로 저장한다. 그래서
`-quality` 를 낮춰도 용량이 거의 안 줄고, 번짐 꼬리에 깔린 옅은 알파
노이즈가 파일 크기를 지배한다. 16 단계로 뭉개면 눈에 띄지 않으면서
6.2MB 가 2.5MB 로 떨어진다. 단, **ffmpeg `-vf scale` 로 크기를 줄이면
알파가 다시 보간돼서 양자화가 무효가 된다** — 해상도는 `-Res` 로 정해라.

**왜 프레임 간 차분(`cr_threshold`)을 안 쓰나.** 용량이 3분의 1 로 줄지만,
회전하는 물체에서는 지나간 자리의 픽셀이 안 지워지고 쌓여서 몇 프레임 만에
형체가 뭉개진다.
