# BeautyTalk

시각장애인·저시력 사용자를 위한 메이크업 도우미 안드로이드 앱.

화면을 보지 않고 **두드리기와 목소리만으로** 씁니다. 어디를 두드려도 되고,
안내는 전부 음성으로 나갑니다.

- **화장품 인식** — 기기 안에서 처리합니다. 네트워크가 필요 없습니다.
- **메이크업 점검** — 사진과 질문을 서버로 보내 한국어 문장으로 답을 받습니다.

`Flutter` · `Android` · `LiteRT(TFLite)` · `Qwen3-VL` · `MediaPipe`

## 동작 방식

```
              ┌─────────────── 기기 안 ───────────────┐
사진 ────────▶│ MobileNetV3-Small (LiteRT)            │──▶ "이건 브러쉬예요"
              │ · 화장품 19종 인식                     │
              │ · 카메라 렌즈 이물질 검사               │
              └───────────────────────────────────────┘

              ┌────────── 서버 (Tailscale) ───────────┐
사진 + 질문 ─▶│ MediaPipe 크롭 → Qwen3-VL 8B (+LoRA)  │──▶ 읽어줄 한국어 한 문단
              │ 질문에 따라 립 / 메이크업 경로로 분기   │
              └───────────────────────────────────────┘
```

음성 인식과 합성도 기기 안에서 합니다(Android STT/TTS, 오프라인 음성).
서버가 없어도 화장품 인식·음성 조작은 그대로 동작합니다.

## 빠른 시작

```bash
flutter pub get
flutter run
```

USB로 연결된 안드로이드 기기에 설치됩니다. 첫 실행 때 **카메라·마이크 권한**을 허용하세요.

| 항목 | 값 |
| --- | --- |
| 패키지명 | `com.skt.beautytalk.beauty_talk` |
| 최소 안드로이드 | 8.0 (minSdk 26) |
| 검증 기기 | Galaxy S24 (Android 15) |
| 플랫폼 | 안드로이드 전용 (iOS 미대응) |

APK만 만들려면:

```bash
flutter build apk --debug
```

### 서버 주소

메이크업 분석만 서버가 필요합니다. 주소는 **빌드할 때 넣습니다** — 저장소에 특정 팀의
사설망 주소를 박아 두지 않으려고 기본값을 비워 뒀습니다.

```bash
flutter run --dart-define=BT_HOST=192.168.0.10
```

주소 없이 빌드하면 메이크업 분석만 꺼지고, **화장품 인식과 음성 조작은 그대로 동작합니다.**

USB로 붙은 기기에서 PC의 서버를 쓰려면:

```bash
adb reverse tcp:8100 tcp:8100
```

서버 띄우는 법은 [sktflyai9th5/beautytalk-backend](https://github.com/sktflyai9th5/beautytalk-backend).

### 기기 없이 연출만 보기

분석 연출(홀로그램 스캔)은 웹 프리뷰로 확인할 수 있습니다.

```bash
flutter run -d chrome -t lib/preview_main.dart
```

> 프리뷰와 홀로그램 테스트가 쓰는 `assets/hologram/demo_face.jpg` 는 **실제 인물 사진이라
> 저장소에 없습니다.** 직접 얼굴 사진을 그 경로에 넣고, 격자 좌표는
> [tools/hologram](tools/hologram/README.md) 으로 다시 뽑으세요.

## 사용법 — 제스처와 음성

화면 **어디를 두드려도** 됩니다. 특정 버튼을 찾을 필요가 없습니다.

| 제스처 | 동작 | 범위 |
| --- | --- | --- |
| 한 번 두드리기 | 음성 인식 시작 | 모든 화면 |
| 두 번 연속 두드리기 | 사진 촬영 | 화장품 · 메이크업 탭 |
| 1.5초 길게 누르기 | 앱 종료 | 모든 화면 |

**마이크는 평소에 꺼져 있습니다.** 두드린 순간부터 한 문장만 듣고 스스로 멈춥니다.
4초 안에 말이 없으면 꺼지면서 "못 들었어요"라고 알려 줍니다 — 조용히 꺼지면 사용자는
죽은 마이크에 대고 계속 말합니다.

| 말하면 | 동작 |
| --- | --- |
| "화장품" / "메이크업" / "설정" (문장으로 말해도 됨) | 해당 탭으로 이동 |
| "처음" / "홈으로" | 화장품 탭 처음 화면으로 |
| "촬영" / "사진" / "찍어" | 촬영 |
| "조용히" / "그만" | 읽던 것 중단 |

인식이 조금 틀려도 동작합니다 — 한글을 자모로 쪼개 편집거리로 비교하고
([`command_matcher.dart`](lib/services/command_matcher.dart)), STT가 주는 **2·3순위 후보까지
전부** 대조합니다. 최종 결과를 기다리지 않고 부분 인식만으로 반응하므로 체감이 빠릅니다.

## 화면 흐름

```
인트로(2.6초, 두드리면 건너뜀) → 진입 화면 → 탭 3개
```

**진입 화면에는 버튼이 하나뿐입니다.** 앞이 보이지 않는 사용자에게 버튼 두 개는
"어느 쪽을 눌렀는지 모르는" 갈림길이라, 할 수 있는 일을 하나로 줄였습니다.

### 화장품 인식 탭 — 온디바이스

`촬영 → 분석 → 결과` 3단계.

카메라가 화면 전체를 채우고 **그 위에 글자를 얹지 않습니다** — 앞이 보이지 않는
사용자에게는 어차피 읽히지 않고, 저시력 사용자에게는 카메라를 가리기만 합니다.
화면 이름도 촬영 안내도 음성으로만 말합니다.

촬영하면 기기 안의 모델이 무엇인지 알려 줍니다. 자신이 없으면(`score < 0.30`)
억지로 답하지 않고 다시 찍으라고 안내합니다. 결과 화면에는 방금 찍은 사진 위에
**모델이 어디를 보고 판단했는지 박스**를 그립니다.

### 메이크업 분석 탭 — 서버

`촬영 → 질문 → 분석 → 결과` 4단계.

1. **촬영** — 셔터를 누르면 서버에 프레이밍을 먼저 확인하고(수십 ms), 쓸 만하면 그
   확인 프레임이 곧 촬영본입니다. 못 쓸 사진이면 촬영을 접고 고칠 방향을 말해 줍니다 —
   20초 기다린 끝에 재촬영을 듣는 것보다 빠릅니다.
2. **질문** — 음성으로 묻거나 추천 질문 중 고릅니다. 촬영 화면에서 바로 질문을 말하면
   질문 화면 없이 분석으로 갑니다. 주변 대화가 그대로 서버로 가지 않도록 **질문형 어미나
   트리거 단어가 있을 때만** 전송합니다.
3. **분석** — 찍은 사진 위로 스캔 연출이 돌고, 음성으로 30·60·90% 지점에서 한 마디씩
   진행을 알립니다. 퍼센트 숫자는 앞이 보이지 않는 사용자에게 아무 그림도 그려 주지 않습니다.
4. **결과** — 사진 위에 위치를 박스로 그리고 `부위 / 상태 / 할 일` 카드를 쌓습니다.
   음성은 서버가 준 문장을 그대로 읽습니다 — 항목을 이어 붙여 다시 만들지 않습니다.

### 설정 탭

목소리·말하는 속도·음 높이를 고릅니다. 눈으로 보고 손으로 만지는 화면이라
**진입할 때 안내 음성을 내지 않습니다.** 선택은 저장되어 앱을 껐다 켜도 유지됩니다.

## 온디바이스 모델

MobileNetV3-Small 백본에 헤드 둘을 붙인 모델을 LiteRT로 돌립니다.

| 헤드 | 출력 | 쓰임 |
| --- | --- | --- |
| `det_head` | `hm(1,48,48,19)` CenterNet 히트맵 + `wh` + `off` | 화장품 19종 인식, 근거 박스 |
| `cls_head` | `cls_logits(1,2)` | 카메라 렌즈 이물질 검사 |

히트맵 전체에서 최고점 하나를 찾아 (클래스, 신뢰도)로 씁니다 — NMS 없이 top-1만.
결과 화면의 박스는 그 최고점을 CenterNet 디코드해 그립니다.

### 렌즈 이물질 검사

탭에 들어올 때와 **셔터를 누를 때마다** 돌리고, 더러우면 촬영을 접고 닦으라고 말합니다.
모델 출력만으로는 부족해서 선명도(라플라시안 분산)와 함께 판정합니다.

| 선명도 | 판정 |
| --- | --- |
| < 55 | **더럽다** — 물 번짐·뿌연 막. 모델이 뭐라 하든 |
| ≥ 150 | **깨끗하다** — 젖은 렌즈는 이렇게 선명할 수 없다. 모델이 뭐라 하든 |
| 그 사이 | `cls_head` dirty ≥ 0.60 이면 더럽다 |

실제 젖은 렌즈 3장을 모델은 1장만 잡았지만(0.97 / 0.03 / 0.03) 선명도는 셋 다 30 아래였고,
깨끗한 렌즈는 121 이상이었습니다. 반대로 점박이 천장 타일은 모델이 0.78~0.92로
"더럽다"고 합니다 — 점을 얼룩으로 읽습니다.

### 모델 교체

앱 코드는 건드릴 필요가 없습니다.

1. `assets/models/cosmetic_both.tflite` 덮어쓰기
2. `assets/models/labels.txt` 를 **학습 때의 클래스 순서 그대로** 갱신
3. 클래스가 바뀌었으면 [`ml/product_catalog.dart`](lib/ml/product_catalog.dart) 에 읽어줄 문장 추가
4. 입력 크기가 다르면 [`ml/model_config.dart`](lib/ml/model_config.dart) 의 `inputSize` 수정

모델 파일이 없거나 로드에 실패하면 자동으로 Mock으로 떨어져서, **모델 없이도 앱은 뜹니다.**

### 임계값

| 값 | 기본 | 의미 |
| --- | --- | --- |
| `scoreThreshold` | 0.30 | 이보다 낮으면 "못 찾음" |
| `dirtyThreshold` | 0.60 | 이보다 높으면 렌즈를 닦으라고 안내 |
| `numThreads` | 4 | LiteRT 스레드 |

> 161장 검증 기준 0.30에서 정답률 71.8%. **0.40으로 올리면** 틀린 답이 33건 → 19건으로
> 줄어드는 대신 "못 찾음"이 늘어납니다.

## 백엔드 연동

`/health` 로 살아있는 포트(8100 → 8000)를 고른 뒤 `ws://<host>/ws/<session_id>` 로 붙습니다.

```jsonc
// 앱 → 서버
{ "type": "analyze", "request_id": "app-1", "question": "립 어때?", "image_b64": "..." }

// 서버 → 앱
{ "type": "analysis_result", "request_id": "app-1", "status": "ok",
  "message": "읽어줄 문장", "route": "lip" }
```

앱은 `message` 만 읽어서 그대로 음성으로 내보냅니다. 재촬영 안내(`status: retake`)도 같은
자리로 오므로 앱은 구분할 필요가 없습니다.

영상은 WebRTC 대신 **스냅샷 방식**입니다(긴 변 1280px, JPEG q88). 서버가 픽셀 단위로
프레이밍을 판정하므로 크게 보내고, 추론 직전에 서버가 640px로 다시 줄입니다.

**대기 시간은 앱 70초 > 서버 60초**입니다. 앱이 먼저 포기하면 다 만든 답을 버리고,
그 요청이 GPU 한 자리를 계속 잡습니다.

노트북 GPU가 절전으로 내려가면 첫 추론이 30~60초 걸려서, 앱 시작·탭 진입·탭 체류 중
주기적으로 `/warmup` 을 부릅니다.

서버가 없으면 실패를 말하고 촬영 화면으로 돌아갑니다. **지어낸 답을 대신 읽지 않습니다** —
앞이 보이지 않는 사용자에게 가짜 분석은 오답보다 나쁩니다.

## 디버깅

`debugPrint` 로그와 잡히지 않은 예외가 `app.log` 에 남습니다(2MB 회전, 최대 2개).

```bash
BASE=/storage/emulated/0/Android/data/com.skt.beautytalk.beauty_talk/files/logs
adb pull $BASE/app.log
adb pull $BASE/speech.log     # 인식된 문장 최근 10건
```

**인식된 음성은 `app.log` 에 넣지 않습니다.** `speech.log` 에 최근 10건만 따로 남고
오래된 것은 지워집니다 — 주변 대화가 파일에 통째로 쌓이지 않게 하면서, 방금 뭘 잘못
알아들었는지는 볼 수 있게 했습니다. 촬영 사진도 캐시에 최근 10장만 남깁니다.
보관 개수는 `LogService.speechKeep` / `CameraService.shotKeep` 이고 0이면 아무것도 남지 않습니다.

## 알려진 제약

- **안드로이드 전용.** iOS 설정은 없습니다.
- **메이크업 분석은 서버가 필요합니다.** 연결이 끊기면 실패를 말하고 촬영으로 돌아갑니다.
  화장품 탭은 온디바이스라 영향이 없습니다.
- **NPU 가속 미적용.** 현재 CPU 4스레드로 돌립니다. QNN/NNAPI delegate를 붙일 훅만 있습니다.
- **렌즈 판정 오탐** — 무늬 없는 벽이나 어두운 방을 비추면 깨끗해도 걸릴 수 있습니다.
- **전면 카메라 미러링은 코드로 판별할 수 없습니다.** 틀리면 좌우 안내가 통째로 뒤집히는데
  사용자가 스스로 확인할 수 없습니다 — 배포 전 실측이 필요합니다([백엔드 저장소](https://github.com/sktflyai9th5/beautytalk-backend#미러링--배포-전-결정할-것)).
- **디버깅용 기록이 기기에 남습니다** — 음성 10건, 사진 10장. 상수로 0까지 줄일 수 있습니다.
